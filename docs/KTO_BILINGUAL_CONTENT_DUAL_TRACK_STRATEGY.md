# KTO 한영 콘텐츠 이중 트랙 전략

> 작성일: 2026-08-25
> 목적: 발표·PM 협의와 관리자 페이지 후속 설계에 사용할 기준 자료

## 1. 결론

KoReady의 기존 KTO 한영 매칭 장소는 그대로 유지한다. 이 데이터는 KTO가 직접 제공한
한국어·영어 정보가 연결된 안정적인 콘텐츠 풀이다.

동시에 KTO 한국어 원문만 있는 장소는 별도의 관리자 후보로 제공한다. 관리자가 사진과
원문을 확인하고 선택한 경우에만 AI가 한국어·영어 편집 콘텐츠를 생성한다.

두 트랙을 섞지 않고 출처를 명확히 구분한다.

| 트랙 | 원본 | 관리자 표시 | 사용자 공개 조건 |
| --- | --- | --- | --- |
| 공식 한영 트랙 | KTO 한국어 + KTO 영어 | `KTO 한영 원문` | 기존 정책 유지 |
| AI 확장 트랙 | KTO 한국어만 | `한국어 원문만` | 관리자 선택 + AI 검증 완료 |

## 2. 현재 데이터 현황

2026-08-25 운영 DB 점검 시점 기준이다. 수집 진행에 따라 일부 숫자는 변할 수 있다.

| 단계 | 장소 수 |
| --- | ---: |
| 전체 KTO 장소 | 68,543 |
| 활성 장소 | 50,663 |
| 활성 장소 중 신뢰 가능한 KTO 영문 매칭 | 9,956 |
| 영문 매칭 + KoReady 7개 유형 분류 | 1,282 |
| 영문 매칭 + 유형 분류 + 이미지 | 1,161 |

현재 관리자 공식 후보 1,161건은 수집 실패로 만들어진 숫자가 아니다. 다음 조건을 모두
만족하는 장소의 교집합이다.

1. 활성 장소
2. KTO 한국어 데이터
3. KTO 영어 또는 운영자가 확정한 영어 데이터
4. KoReady의 7개 여행 유형 중 하나 이상
5. 이미지 한 장 이상

영문과 유형을 만족하지만 이미지가 없는 121건은 상세·사진 API 조회까지 완료됐으나 KTO가
추가 이미지를 제공하지 않은 장소다. 현재 정책만 유지하면 1,161건이 자동 확보 가능한
안정 풀의 사실상 상한이다.

## 3. 왜 기존 한영 트랙을 유지하는가

- KTO 공식 영문이므로 출처와 책임 범위가 명확하다.
- 영어 장소명·주소·설명을 그대로 사용자 API에 활용할 수 있다.
- 한국어 화면에서도 영문 보유 여부를 공개 안전성 조건으로 사용하고 있다.
- 추천, 장소 목록, 검색, 상세, 저장 장소, 온보딩 등 여러 API가 이 조건을 공유한다.
- 이미 정상 동작하는 1,161건의 품질을 새로운 실험 때문에 낮출 이유가 없다.

발표에서는 이를 데이터 부족으로만 설명하지 않는다. 공공데이터의 다국어 범위와 KoReady의
서비스 분류·이미지 품질 조건을 함께 적용해 만든 **검증된 초기 콘텐츠 풀**이라고 설명한다.

## 4. 한국어 원문 기반 AI 확장 트랙

영문 필수 조건만 제외하면 이미지와 서비스 유형이 있는 한국어 장소 후보는 13,018건 더
존재한다. 다만 모든 장소가 즉시 AI 처리 가능한 것은 아니다.

- 관리자 화면에 표시 가능한 한국어 전용 후보: 약 13,018건
- 현재 한국어 설명까지 있어 즉시 AI 큐에 넣을 수 있는 후보: 약 368건
- 나머지는 KTO 상세 설명 적재가 끝난 뒤 순차적으로 처리 가능

AI 확장 트랙은 일괄 자동 생성하지 않는다. 다음 두 행동만 비용 발생 트리거로 사용한다.

1. 관리자가 장소를 선별해 AI 가공을 요청한다.
2. 향후 정책이 확정되면 사용자가 검색 결과에서 해당 장소 상세에 진입한다.

MVP에서는 관리자 선별을 우선한다. 사진과 원문이 좋은 장소만 처리해 비용을 통제하고 발표와
실사용 화면의 품질을 빠르게 높일 수 있다.

## 5. 관리자 페이지 제안

구현 API는 `GET /api/v1/admin/editorial/candidates`의 `sourceTrack` 필터를 사용한다. 값은
`KTO_BILINGUAL`, `KOREAN_ONLY_AI`, `ALL`이며 생략 시 기존 공식 한영 후보만 반환한다. 응답의
`sourceTrack`과 `hasTrustedEnglish`로 관리자 화면 배지와 안내 문구를 결정하고,
`queueEligible=true`인 한국어 전용 후보는 기존 큐 등록 API로 처리한다.

장소 후보 화면에 다음 탭 또는 빠른 필터를 둔다.

### 5.1 KTO 한영 원문

- 기존 1,161건을 그대로 표시
- 배지: `KTO 한영 원문`
- 한글명과 KTO 영문명을 함께 표시
- 기존 AI 가공 요청 흐름 유지

### 5.2 한국어 원문만

- KTO 공식 영문이 없는 장소만 표시
- 배지: `한국어 원문만`
- 안내 문구:

> KTO 공식 영문이 없는 장소입니다. AI가 한국어 원문과 상세 사실을 바탕으로 한국어·영어
> 콘텐츠를 생성합니다. 생성된 영어는 KTO 공식 번역이 아닙니다.

- 원문이 충분하면 버튼: `AI 한·영 콘텐츠 생성`
- 한국어 설명이 부족하면 버튼을 비활성화하고 `상세 원문 수집 대기` 표시
- 결과 화면의 영어 탭에 `AI 생성 영문` 배지 표시

권장 필터:

- 권역
- 여행 유형
- 한국어 설명 보유 여부
- 이미지 수
- AI 처리 상태
- 공개 여부

## 6. 처리 흐름

1. 백엔드가 영문 보유 여부를 판정한다.
2. 관리자는 한국어 전용 후보의 사진, 제목, 설명, 유형과 상세 사실을 확인한다.
3. 관리자가 선택하면 `HIGH` 우선순위로 AI 큐에 등록한다.
4. AI는 한국어 원문과 구조화된 KTO 상세 사실만 사용한다.
5. 한 번의 구조화 응답으로 한국어·영어 편집 콘텐츠를 생성한다.
6. 서버가 글자 수, 태그 수, 즐길 거리 수와 금지 조건을 검증한다.
7. 검증에 성공한 결과만 `READY`로 저장한다.
8. AI 확장 트랙은 `READY`가 된 장소만 사용자 API에 공개한다.

기존 공식 한영 트랙은 이 변경의 영향을 받지 않는다.

## 7. 데이터 출처와 저장 원칙

AI가 생성한 영어를 KTO 공식 영문처럼 저장하면 안 된다.

- KTO 원문: `place_localizations.translation_source = KTO_EN`
- 운영자 수정: `MANUAL_EDITED`
- AI 번역이 필요한 장소명·주소: `AI_TRANSLATED`
- AI가 만든 주제·설명·즐길 거리:
  `place_editorial_contents`, `place_editorial_localizations`

현재 편집 파이프라인은 한국어·영어 주제, 한줄설명, 간단소개, 즐길 거리와 태그를 분리 저장할
수 있다. 따라서 기존 KTO 영문을 덮어쓸 필요가 없다.

AI 편집 응답은 영어 장소명과 영어 주소도 생성한다. 검증에 성공하면 영어 간단소개와 함께
`place_localizations`에 `AI_TRANSLATED` 출처로 저장한다. 따라서 목록·검색·추천·상세·저장 장소와
온보딩 후보는 READY 상태의 AI 영어 데이터를 기존 영어 현지화 조회 경로에서 사용할 수 있다.
AI 작업이 실패했거나 READY 결과가 없으면 사용자 공개 조건으로 인정하지 않는다.

KTO 공식 영문이 나중에 매칭되면 `KTO_EN`을 우선한다. 기존 AI 결과의 원문 지문을 변경해
`STALE`로 만들고 필요할 때 재생성한다.

## 8. 공개 API 변경 원칙

현재 여러 사용자 API는 KTO 공식 영문 존재를 무조건적인 공개 조건으로 사용한다. 이 조건을
단순 삭제하지 않고 다음과 같이 확장한다.

```text
공개 가능 = 기존 KTO 영문 보유
          OR (한국어 원문 기반 AI 결과 READY AND 관리자 선택 이력 보유)
```

영어 응답 우선순위:

1. 운영자가 수정한 영어
2. KTO 공식 영어
3. 검증 완료된 AI 영어
4. 정책상 허용된 경우에만 한국어 fallback

이를 통해 기존 1,161건의 응답은 바뀌지 않고, 새 AI 장소만 안전하게 추가된다.

## 9. 비용 및 품질 안전장치

- 한국어 전용 후보를 일괄 큐에 넣지 않는다.
- 관리자 목록 조회만으로 AI를 호출하지 않는다.
- 같은 원문 지문과 프롬프트 버전은 중복 생성하지 않는다.
- 장소당 재시도 횟수와 일일 처리량을 제한한다.
- 한국어 원문이 부족하면 `INSUFFICIENT_SOURCE`로 실패시킨다.
- 생성 실패 장소는 공개하지 않는다.
- AI 생성 영문이라는 출처를 관리자 화면과 감사 로그에 남긴다.
- KTO에 없는 프로그램, 시설, 음식, 역사와 운영정보를 만들지 않는다.

## 10. 발표용 설명

### 문제

한국관광공사 데이터는 한국어 장소가 약 6.8만 건이지만, 영어 정보·서비스 유형·이미지를 모두
충족하는 장소는 약 1,100건이다. 단순히 번역만 붙이면 출처와 사실성이 불명확해질 수 있다.

### 해결

KoReady는 공공기관이 제공한 한영 데이터를 안정 풀로 보존한다. 한국어 데이터만 있는 장소는
운영자가 사진과 원문을 확인한 뒤 선택적으로 AI를 사용한다. AI 결과는 공식 번역과 구분해
저장하고, 자동 검증을 통과한 콘텐츠만 서비스에 추가한다.

### 효과

- 검증된 기존 콘텐츠의 품질 유지
- AI 비용을 관리자가 선택한 장소에만 사용
- 한국어 중심의 지역 관광지를 점진적으로 다국어화
- 데이터 출처와 AI 생성 여부를 추적 가능
- MVP에서는 적은 수의 양질 콘텐츠로 시작하고 운영 과정에서 확장 가능

## 11. 확정된 구현 기준

1. 관리자 큐 등록과 AI 검증 성공을 공개 조건으로 사용한다.
2. AI가 영어 장소명, 주소와 영어 간단소개를 생성한다.
3. AI 영어는 `AI_TRANSLATED`로 저장하고 KTO·운영자 영문을 덮어쓰지 않는다.
4. 사용자 응답의 콘텐츠 출처는 `AI_GENERATED`로 구분한다.
