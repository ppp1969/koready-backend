# KTO Rule Base v1 Dry Run 결과

## 실행 목적

PM이 승인한 KTO 분류 규칙을 현재 Aiven 데이터에 저장하기 전에 적용해 보고,
각 유형의 실제 후보 수와 사용자 노출 영향도를 확인했다.

이번 실행은 외부 KTO API를 호출하지 않는다. Aiven의 `places`,
`place_images`, `place_style_mappings`를 읽기 전용 연결로 조회했으며 Flyway,
스케줄러, 데이터 변경 기능은 모두 비활성화했다.

## 실행 기준

- 실행 일시: 2026-08-05
- 규칙 버전: `kto-place-style-v1`
- 대상: KTO에서 수집된 전체 장소
- 사용자 노출 기본 조건: KoReady 유형이 있고 이미지가 1장 이상인 장소
- 수동 분류: 기존 `MANUAL` 매핑을 자동 규칙보다 우선해 함께 인정
- 반복 검증: 같은 조건으로 다시 실행했을 때 동일한 결과 확인

## 확인된 최우선 리스크

현재 공개 플래그가 켜진 장소는 3,869곳이지만 확정 유형까지 가진 장소는
873곳이다. 분류 결과를 DB에 저장하기 전에 사용자 API에 유형 필터를 먼저
적용하면 기존 공개 데이터가 약 77.4% 감소할 수 있다.

따라서 다음 순서를 지켜야 한다.

1. 분류 규칙 버전과 분류 근거를 저장할 DB 구조를 추가한다.
2. 기존 68,543곳에 Rule Base v1을 일괄 적용한다.
3. 이미지, 공개 상태, 유형별 수치를 다시 검증한다.
4. 검증이 끝난 뒤 사용자 API에 이미지 및 유형 노출 조건을 적용한다.

## 해석 및 후속 결정

- 이미지가 있고 최종 분류된 17,030곳은 AI 소개문이나 번역 없이도 기본 카드
  후보로 사용할 수 있다.
- 미분류 46,855곳은 삭제하지 않는다. KTO 원본 코드와 장소 정보는 보존하고
  향후 신규 유형 또는 운영자 검수에 활용한다.
- 현재 복수 유형이 0곳이므로 대표 유형 우선순위는 즉시 노출을 막는 문제는
  아니다. 다만 수동 분류 확대 전에 대표 유형을 명시적으로 저장할 구조는
  필요하다.
- 수동 분류 10건은 자동 분류 작업이 덮어쓰지 못하도록 해야 한다.
- 이 결과는 후보 통계이며 DB 일괄 분류와 사용자 API 변경을 수행한 결과가
  아니다.
