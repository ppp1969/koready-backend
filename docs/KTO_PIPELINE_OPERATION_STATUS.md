## 이미 적용된 동작

### 장소 상세 보강

장소 하나를 보강할 때 KTO API를 다음 순서로 호출한다.

1. `detailCommon2`: 제목, 설명, 주소, 좌표, 대표 이미지
2. `detailIntro2`: 관광 유형별 운영시간, 휴무일, 요금, 주차 정보
3. `detailInfo2`: 반복 상세 정보
4. `detailImage2`: 갤러리 이미지

성공한 원문은 private S3에 저장하고, 서비스 DB에는 필요한 정규화 데이터와 원문 hash,
저장 위치 같은 메타데이터만 남긴다. 이미 완료된 장소는 30일 갱신 시점 전까지 다시
호출하지 않으므로 중단 뒤에도 미완료 장소부터 이어서 처리한다.

초기 200개 표본에서 네 종류 호출과 S3 저장은 모두 성공했다. KTO 상세 사진만 놓고 보면
4장 미만인 장소가 34.5%였고, 대표 이미지 fallback을 적용한 실제 갤러리는 0장인 장소가
없었다. 따라서 "모든 장소에 정확히 4장"을 전국 장소에 강제하는 것은 데이터 원본의 한계와
맞지 않는다. 승인된 온보딩 장소에만 4장 보장을 적용한다.

### 이미지 조합 순서

공개 장소 상세 API는 URL 중복을 제거한 뒤 다음 순서로 최대 4장을 반환한다.

1. 운영진이 승인해 연결한 KTO 사진공모전 수상작
2. KTO 대표 이미지 (`firstimage`)
3. KTO 상세 이미지 (`detailImage2`)

사진공모전의 장소 식별자는 일반 관광지 식별자와 직접 같다고 보장되지 않는다. 제목이
비슷하다는 이유만으로 자동 연결하지 않고, 운영진이 실제 사진과 장소를 확인한 매핑만
노출한다.

### 연관 관광지의 한도 복구

제주처럼 한 지역의 결과가 20페이지를 넘는 경우를 확인해 지역별 페이지 상한을 50으로
확대했다. 이후 KTO의 일일 호출 한도 응답이 발생했을 때는 실패 지점과 파라미터를 보존하고,
다음 날 00:15(한국 시간)에 최신 실패 작업만 한 번 재개하도록 했다. 재개 체인은 완료되면
새 작업을 만들지 않는다.

## 상세 전수 수집의 현재 제약

현재 EB 자동 스케줄은 하루 50개 장소만 상세 보강한다. 장소당 최대 4회 호출이므로 최대
200회/일이다. 이는 KTO 한도를 넘기지 않고 Aiven과 EB의 안정성을 우선한 시작값이다.

대상 약 68,500개를 이 값으로만 처리하면 최초 보강에 약 1,370일, 즉 약 3.7년이 걸린다.
따라서 이 설정은 **안전한 상시 보강 장치**이지, 빠른 전수 완료 계획은 아니다.

빠른 전수 보강을 시작하려면 아래 중 하나를 먼저 결정해야 한다.

| 선택지 | 장점 | 확인할 위험 |
| --- | --- | --- |
| 현재 50개/일 유지 | 호출 한도와 운영 부하가 가장 낮음 | 서비스 범위 확대 속도가 매우 느림 |
| 단계 확대 (예: 50 -> 100 -> 200) | 실제 성공률을 보며 속도를 올릴 수 있음 | 200개/일은 최대 800회 호출이므로 KTO 한도 확인 필요 |
| 우선순위 보강 | 프론트에 먼저 보일 장소의 상세·사진 품질을 빠르게 확보 | 전국 전수 완료와 별도의 우선순위 기준 필요 |
| KTO 제공 한도 상향 후 전수 실행 | 가장 빠르게 완료 가능 | 제공 한도, 비용, 오류 재개·모니터링 기준 확정 필요 |

현재 코드의 상한은 50개/일이며, 임의로 높이지 않는다. 실제 KTO 일일 허용량이나 우선순위
목록이 확정되면 해당 변경은 별도 이슈에서 RED-GREEN-REFACTOR와 단계별 운영 검증을 거쳐
진행한다.

## 남은 운영 확인

1. AWS 로그인 세션으로 관리자 데이터 품질 API를 조회해, 자동 스케줄 이후의 최신 완료 수와
   0~4장 사진 분포를 기록한다.
2. 50개/일 자동 작업의 여러 날 연속 성공률, KTO 429/5xx, EB 메모리, S3 저장 실패를 확인한다.
3. 실제 사진을 검수한 뒤 사진공모전 후보를 장소에 승인 매핑한다.
4. 상세 화면 API 표본을 프론트·디자인 시안과 대조해 이미지 순서, fallback, 설명 영역을
   확인한다.

## 아직 시작하지 않은 제품 기능

- AI 기반 장소 소개문 생성·검수: #112. 실제 AI provider, 모델, 월 비용 한도 결정이 선행돼야
  한다. 요청 시점 생성은 하지 않고, 배치 생성 후 운영진 검수·발행하는 구조로 설계돼 있다.
- 소셜 로그인: 의도적으로 후순위다. 지금의 공개 데이터 API와 KTO 수집에는 필요하지 않다.
- TMAP 연동: 후순위다. 현재 Buddy Route의 기본 장소·경로 데이터와 별개로 다룬다.

## 운영 중단 기준

다음 중 하나가 발생하면 상세 보강 확대를 멈추고 원인을 확인한다.

- KTO `429` 또는 `5xx` 비율이 2% 초과
- DB 또는 S3 저장 실패가 연속 5건
- EB readiness 실패, 재시작, 메모리 압박
- 사진 URL 유효성 실패가 표본의 10% 초과
