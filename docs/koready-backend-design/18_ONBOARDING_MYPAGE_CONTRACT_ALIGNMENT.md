# 온보딩·마이페이지 계약 정합성

## 목적

이 문서는 2026-08-02 기준 온보딩과 마이페이지 요구사항을 API, 저장 규칙, 화면 호출 흐름에 맞춰 정리한다. KTO 수집과 AI 소개·번역은 이번 범위에 포함하지 않는다.

## 확정 규칙

| 영역 | 규칙 |
|---|---|
| 위치 검색 | 키워드로 최대 20개 후보를 반환한다. 후보에는 장소명, 도로명주소, 지번주소, 좌표, 서비스 권역, 저장용 서명 토큰이 포함된다. |
| 우편번호 | 카카오 주소 검색 결과에 있으면 검색 응답에 포함한다. 키워드 검색 결과에 없으면 사용자가 저장할 때 좌표 기반 주소 조회로 한 번 보완한다. |
| 위치 이력 | 저장한 위치는 사용자별 목록으로 조회하며 기본 위치를 다시 선택하거나 삭제할 수 있다. 삭제는 DB에서 즉시 지우지 않고 숨김 처리한다. |
| 온보딩 여행 스타일 | 7개 중 정확히 4개를 선택해야 온보딩을 완료할 수 있다. |
| 운영자 추천 장소 | 발행된 후보 세트는 정확히 10개이며 사용자는 1~3개를 선택한다. 각 장소는 화면용 핵심 태그를 2~3개 가진다. |
| 프로필 여행 스타일 | 온보딩과 같은 저장값을 사용하며 1~4개까지 수정할 수 있다. |
| 프로필 SNS | Instagram, TikTok, WeChat, Xiaohongshu, LINE, KakaoTalk 중 최대 2개를 공개 ID와 함께 저장한다. |
| 앱 표시 언어 | MVP는 KO와 EN만 제공한다. 로그인 사용자는 프로필에 저장한 언어가 우선이고, 비로그인 조회는 `Accept-Language`를 따른다. |
| 좋아하는 장소 | 로그인 사용자의 장소 목록·검색·상세·월별 추천·홈·추천 덱 응답은 실제 저장 여부를 `saved` 또는 `isSaved`로 반환한다. 비로그인 조회는 `false`다. |

## 화면 호출 흐름

### 온보딩

1. `GET /api/v1/locations/search?query=...&limit=20`으로 위치 후보를 검색한다.
2. 사용자가 고른 항목의 `searchResultToken`을 `POST /api/v1/users/me/locations`에 전달한다.
3. 저장 응답에서 도로명주소, 지번주소, 우편번호와 `locationId`를 받는다.
4. `GET /api/v1/onboarding/place-candidate-sets/current`로 운영자가 발행한 10개 장소와 장소별 태그 2~3개를 조회한다.
5. 위치 1개, 여행 스타일 4개, 후보 장소 1~3개를 `PUT /api/v1/users/me/onboarding`에 한 번에 제출한다.

### 마이페이지

1. `GET /api/v1/profile-options`로 국적, 사용 언어, 한국어 수준, 여행 스타일, SNS 선택지를 조회한다.
2. `GET /api/v1/users/me/buddy-profile`로 현재 프로필을 조회한다.
3. `PUT /api/v1/users/me/buddy-profile`로 닉네임, 국적, 사용 언어 복수 선택, 한국어 수준, 한 줄 소개, 여행 스타일, SNS, 공개 설정을 저장한다.
4. 프로필 이미지는 업로드 URL 발급과 완료 API를 거쳐 얻은 서버 경로만 프로필에 저장한다.
5. `PATCH /api/v1/users/me/language`로 앱 표시 언어를 바꾼다. 이후 로그인 상태의 지역·장소·추천 API는 저장된 언어를 자동 적용한다.
6. `GET /api/v1/users/me/locations`에서 위치 이력을 조회하고 기본 위치 변경 또는 삭제 API를 호출한다.

### 좋아하는 장소

1. 장소 카드와 상세 응답의 `saved` 또는 `isSaved`를 그대로 하트 초기 상태로 사용한다.
2. 선택은 `PUT /api/v1/users/me/saved-places/{placeId}`, 해제는 `DELETE /api/v1/users/me/saved-places/{placeId}`다.
3. 여러 카드의 저장 여부는 서버가 한 번의 묶음 조회로 계산하므로 프론트가 카드마다 별도 확인 API를 호출하지 않는다.

## 데이터 변경

- `user_locations.postal_code`를 추가한다.
- `user_travel_styles.display_order`는 1~4만 허용한다.
- `buddy_social_links.link_type`은 확정된 SNS 6종만 허용한다.
- `onboarding_candidate_set_items.display_tags_json`은 배열 길이 2~3만 허용한다.
- 기존 운영 데이터에서 여행 스타일 4개 초과, 후보 태그 2~3개 이탈, 구형 SNS 값이 없는지 마이그레이션 전에 확인한다.

## 호환성과 제외 범위

- 기존 위치 검색 토큰에 우편번호가 없어도 검증할 수 있으며, 저장 시 보완 조회한다.
- 로그인 사용자가 DB에 아직 생성되지 않은 테스트 상황에서는 `Accept-Language`로 안전하게 대체한다.
- 삭제한 위치를 다시 활성화하는 복원 API는 제공하지 않는다.
- 온보딩에서 선택한 운영자 추천 장소를 마이페이지에서 다시 편집하는 API는 별도 요구사항으로 분리한다.
- KTO 수집, AI 소개·번역, 소셜 로그인 변경은 이 계약의 범위 밖이다.
